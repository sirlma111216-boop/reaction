# 하지 않은 것과 알려진 한계

## 하지 않은 것

- **사람 플레이테스트**: 봇 시뮬레이션으로만 밸런스를 맞췄다. 봇의 승률이 비슷하다고 학생에게 재미있다는 뜻은 아니다.
- **학교 무선망 실측**: 30대 동시 접속은 로컬 `wrangler dev` 에 교사 1명 + 학생 30명을 붙인 통합 테스트(`scripts/e2e-ws.mjs`, 64항목)로만 확인했다. 실제 교실 무선망에서의 지연·끊김은 재지 않았다.
- **배포와 교사 비밀번호 등록**: 로컬 커밋까지만 했다. `wrangler secret put TEACHER_PASSWORD` 와 `npm run deploy` 는 사용자가 한다.
- **그림·소리 파일**: 96개 그림과 35개 소리 자리만 있다. 파일이 없는 상태로 모든 화면을 확인했다.
- **교과서 대조**: 성취기준 코드·단원 이름과 반응 예시(탄산수소 나트륨 분해, 산화 칼슘과 물, 탄산수소 나트륨과 시트르산)는 2차 정리 자료로 확인했다. `docs/CURRICULUM.md` 의 「교과서로 확인 필요」 열을 보라.
- **입자 모형 그림**: 이미지 생성기가 정확히 그리지 못하므로 자산 목록에 넣지 않았다. 필요하면 교과서 그림을 기준으로 따로 준비한 그림 자리를 추가해야 한다.
- **화면의 자동 접근성 검사**: 키보드 조작·포커스 표시·대비는 CSS 로 챙겼지만 자동 검사 도구(axe 등)는 돌리지 않았다.

## 알려진 한계

- **본문 글꼴의 CSS 크기**: Pretendard 동적 서브셋을 npm 패키지로 묶어 CDN 을 부르지 않는다. 글리프 묶음마다 `@font-face` 가 있어 빌드된 CSS 가 약 970 KB(gzip 427 KB)이고, 정적 자산 파일이 2,100개 남짓이다. 실제 내려받는 글꼴 조각은 화면에 쓰인 글자 범위만이지만, 첫 로딩에서 CSS 가 크다. 가벼운 대안: `pretendard/dist/web/static/Pretendard-Regular.css` 와 `Pretendard-Bold.css` 만 쓰면 CSS 는 작아지지만 글꼴 파일 하나가 더 크다.
- **교사 로그인 제한**: 같은 IP 에서 1분에 10번은 Directory Durable Object 의 메모리에서 센다. DO 가 휴면에서 깨어나면 카운터가 초기화된다. 학교처럼 한 공인 IP 를 여러 명이 쓰는 곳에서는 교사 여러 명이 동시에 로그인하면 제한에 걸릴 수 있다.
- **방 코드 충돌**: 6자리 코드를 5번까지 다시 뽑는다. 동시에 방을 많이 만들면 드물게 실패 메시지가 나올 수 있다(다시 누르면 된다).
- **단체 주문의 보너스 표시**: 설정값을 그대로 보여 주므로, 밸런스 조정으로 값이 바뀌면 화면도 따라 바뀐다. 문서의 수치(팁 4, 보너스 6)는 현재 설정 기준이다.
- **마지막 날의 하룻밤 음식**: 만들 수는 있지만 완성되지 않아 폐기된다. 화면에서 미리 알려 주지만 막지는 않는다(규칙 10.1).
- **학생 투영의 추천 표시**: 최근 12개만 보낸다. 10초에 6번 제한은 서버가 센다.
- **관전자**: 경기 중에 들어온 학생은 「구경하는 중」 화면만 본다. 교사가 대기실에서만 팀에 넣을 수 있으므로, 경기 중 늦게 온 학생을 팀에 넣으려면 `movePlayer` 를 쓰는 교사 보드 조작이 없다. 대기실에서 모두 들어온 뒤 시작하는 것을 전제로 했다.
- **M08 액체 제시 순서**: (메뉴판, 날짜, 팀)으로 섞는다. 시드를 쓰지 않으므로 같은 날짜·팀이면 다른 방에서도 같은 순서다. 연출일 뿐 규칙에는 영향이 없다.
- **밸런스 수치는 봇 기준**: 장비 메뉴의 인분당 가격을 초깃값보다 3코인 올렸다(`docs/DECISIONS.md`). 학생이 봇과 다르게 행동하면 다시 조정해야 할 수 있다. `npm run sim:validate` 로 언제든 다시 잴 수 있다.
